# ADR-0017 (proposed): Manuscript in the ACM acmart LaTeX template

> **Status: proposed (claude-proposed).** This is a default Claude suggested in session 1 ([raw/01-scoping-decisions.md](../raw/01-scoping-decisions.md), "Claude defaults proposed"). The owner has **not** approved it. It becomes `accepted` only after owner approval in the plan app ([SCHEMA §10.4](../SCHEMA.md#104-rules)).

## Context

The master prompt says: "Use an established academic LaTeX template appropriate to the eventual venue". It gives the working title *Adaptive Resource Management for Chromium-Based Desktop Web Containers: Design and Experimental Evaluation* and a section list ([raw/00-master-prompt.md](../raw/00-master-prompt.md) §13). AI usage must follow the applicable publication policy (§14).

**The venue is not chosen** (open question Q-124). The seed related work spans:

- ACM venues: WWW 2012, CHI 2021, ISMM/OOPSLA/ASPLOS methodology papers, TOMPECS;
- IEEE venues: CLUSTER 2021, S&P 2021;
- USENIX venues: Security 2019, ATC 2020, USITS '97.

Sources: [raw/research/related-work-seed.md](../raw/research/related-work-seed.md), [raw/research/measurement-methodology.md](../raw/research/measurement-methodology.md) §7.6. So no single publisher is implied.

## Options considered

| Option | Pros | Cons |
|---|---|---|
| A. **ACM acmart, provisional `sigconf`** | One class covers many ACM conference and journal formats, so switching format is a class option. Widely used for systems and measurement venues | Wrong if the venue is IEEE or USENIX, which would mean porting later. The current acmart version was not researched: UNVERIFIED[phase-p8-research-paper] |
| B. IEEEtran | Standard for IEEE venues | Same porting risk in the other direction |
| C. USENIX template | Fits USENIX systems venues | Same porting risk |
| D. Defer; plain `article` class until the venue is chosen | No premature commitment | Page-limit and formatting surprises come late. Figures may need resizing |

## Decision

**Option A as a provisional default**, under these rules:

- Manuscript sources go in `research/paper/` ([ADR-0018](adr-0018-repo-root-cargo-workspace.md)).
- Content is written so it can be ported between templates: no class-specific macros in the body text, and figures generated by scripts at the target column width ([ADR-0013](adr-0013-statistics-python.md)).
- The template is **re-decided when the venue is chosen**, through a superseding ADR if the venue is not ACM.
- **No results section is written** until experiments are complete and analysed (master prompt §13). No citation enters the bibliography unless it is verified in a research note.

## Consequences

### Positive

- The manuscript skeleton can start in P8 without waiting for a venue decision.

### Negative

- If the eventual venue is IEEE or USENIX, there is a porting cost, kept low by the portability rules above.
- A LaTeX distribution must be installed via winget; Claude runs the install per [ADR-0021](adr-0021-claude-runs-toolchain-installs.md) (superseding ADR-0005). That it installs and builds the class here is UNVERIFIED[phase-p8-research-paper].
- The venue's AI-disclosure policy is unknown and must be checked before submission: UNVERIFIED[phase-p8-research-paper].

### Follow-ups

- Owner: approve or reject this ADR, and answer Q-124 (venue, in [ov-open-questions](../overview/ov-open-questions.md)) when results exist. Recommended default: decide once P7 results exist and the P8 literature review has scoped any novelty claim; until then draft in `acmart` (`sigconf`), written to port easily, and plan an arXiv preprint alongside the venue submission.
- P8: fetch and record the template version and the venue's AI policy in a research note.
