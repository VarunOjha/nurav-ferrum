## 1. The request

Context: the owner was walking through portal v2 (the STATUS next action) and wanted a way to point at parts
of the page when he gives feedback on the layout.

Owner's words (verbatim, Claude Code chat, relayed to the implementing Claude session by the workflow that ran it):

> Reviewing the portal now, before we proceed, let's add a ref button. So that when I click the ref button, it can outline how the UI components are present on the planning portal. I can then use that to provide feedback on the layout of the planning portal

## 2. The chosen design

The workflow that relayed the request named the design option as **"Outline + labels + copy"**: a Ref toggle
in the portal header; when on, every block on the current tab and in any open popup gets a dashed outline and a
small label "<id> · <plain name>"; clicking a label copies "<tab or popup> › <id> <name>" for the feedback; Esc or
the button turns it off; the ids are fixed in one registry so they do not change when the plan text changes; a
"Layout map" lists every id. The option name is recorded here as the workflow stated it, not as the owner's
verbatim words.

Meaning, as recorded: a planning-tool feature of the read-only portal (`interactive_plan/`, task p0.17). It
changes no plan content and no approval, and it is not Ferrum application code.
