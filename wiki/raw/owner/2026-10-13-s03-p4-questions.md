## 1. Q-112 (exact behaviour for `http:` URLs)

Question: "Q-112: what should Ferrum do when an address starts with plain http (not https)?" Options offered:
- "Try HTTPS, else warn (Recommended)": "Always try the secure version first. If that fails, show a warning page with
  'Continue over HTTP (this time)' and an optional 'remember for this site'. Each continue is logged."
- "Try HTTPS, else block": "Same first step, but if the secure version fails the site does not open. Safer, but some old
  sites and home routers will not work."
- "Allow HTTP with a warning bar": "Open HTTP sites as they are, with a visible 'not secure' bar. Least friction, least
  protection."

Owner's answer:

> Allow HTTP with a warning bar

## 2. Q-113 (blocklist default contents and source)

Question: "Q-113: what should Ferrum's list of blocked sites contain when it is first installed?" Options offered:
- "Empty, you add sites (Recommended)": "Ships empty (plus a few made-up test addresses used only by the security tests).
  You add sites in Settings. No outside lists until their licences and update process are checked."
- "Start with a public list": "Ship a well-known public malware or phishing list. Claude first researches licence and
  update options and comes back to you, which delays P4."

Owner's answer:

> Empty, you add sites (Recommended)

## 3. Q-212 (runtime flags versus build features)

Question: "Q-212: how should Ferrum switch its security and isolation options for experiments?" Options offered:
- "Settings in one app (Recommended)": "One Ferrum program; options such as isolation mode are chosen in its settings
  file. The only exception is a separate test-only build with security turned off, used to measure what security costs.
  That build never ships."
- "Separate builds per option": "A different Ferrum program for each option. Cleaner comparisons in theory, but many
  more builds to make and keep in step."

Owner's answer:

> Settings in one app (Recommended)

## 4. Meaning recorded by Claude

- Q-112: an `http:` address is loaded over HTTP as typed, without an automatic HTTPS upgrade attempt, and the shell shows
  a visible "not secure" warning bar while the page is on HTTP. This narrows the owner's Q12 words "HTTP upgraded/warned"
  (raw/01-scoping-decisions.md) to the "warned" branch. Rule 1 of adr-0015 is updated to match.
- Q-113: the blocklist ships empty apart from the security-suite fixture domains; the owner adds sites in Settings; no
  third-party lists until their licences and update process are reviewed.
- Q-212: runtime settings on one identical binary for security policies, isolation modes and lifecycle strategies; the
  only build-time exception for P4 is the benchmark-only `cfg-ferrum-nosecurity-bench` feature (never in release builds).
  The optional compile-time feature for the experimental adaptive lifecycle code (P7) is part of the same proposal.
