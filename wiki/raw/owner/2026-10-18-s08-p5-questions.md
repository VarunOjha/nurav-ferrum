## 1. Q-114 network log (three questions)

Question 1: "Phase 5 builds a network log: a list of the web addresses Ferrum loads (never page contents or passwords).
It stays on your PC, outside the project folder. Some addresses carry login codes after the "?" (for example
...?token=abc123). What should the log keep?" Options: "Cut after "?" (Recommended)" (codes dropped; full addresses can
be switched on in Settings) and "Keep full addresses" ("Everything is kept, codes included. More detail for checking
what a site did, but the log file then holds sensitive codes.").

> Keep full addresses

Question 2: "Should the network log run all the time, or only when you switch it on?" Options: "Only when switched on
(Recommended)" ("Off by default; you turn it on in Settings when you want to review a site's activity. Since full
addresses are kept, this keeps login codes off disk most of the time. Benchmark runs switch it on themselves.") and
"Always on".

> Only when switched on (Recommended)

Question 3: "How long should Ferrum keep old network logs before deleting them by itself? (Only the log files Ferrum
wrote; you can change it later in Settings.)" Options: "14 days (Recommended)", "7 days", "30 days", "Never delete".

> 14 days (Recommended)

## 2. Q-115 startup measure

Question: "Your original brief asks to measure "time to interactive" at startup. The standard tool dropped that measure
as unreliable. Replace it with four clear moments: program started → window shown → first content drawn → main content
drawn, plus a check for long freezes? The paper would say why the old measure was not used." Options: "Replace it
(Recommended)" and "Keep the old measure too".

> Replace it (Recommended)

## 3. Q-203 raw run data

Question: "Where should raw measurement data from benchmark runs be kept? Some trace files can be very large (hundreds of
MB), too big for git." Options: "Split by size (Recommended)" (small files in git, files over 10 MB in a local folder
not uploaded, fingerprints in git), "Everything in git" ("Simplest to share, but the project grows by gigabytes and
GitHub may refuse large files.") and "Everything outside git".

> Everything in git

## 4. Meaning recorded by Claude

- Q-114: the network log keeps full URLs (query strings included); it is off by default and switched on in Settings
  (benchmark runs switch it on themselves); log files older than 14 days are deleted by Ferrum (changeable in
  Settings). Location was not asked: the adr-0008 default stands (`%LOCALAPPDATA%\Ferrum\netlogs\`, outside the repo).
  The adr-0008 rule stays that a log copied into `wiki/raw/bench/` carries only test or approved public addresses with
  query values redacted.
- Q-115: "time to interactive" is not measured; the startup chain is process start → window visible → first contentful
  paint → largest contentful paint, plus long-frame (LoAF) blocking for responsiveness; the paper says why.
- Q-203: all raw run data goes in git under `wiki/raw/bench/<run-id>/` (SCHEMA §3.1). Claude told the owner after the
  answer that GitHub refuses single files over 100 MB, so the largest trace files may need GitHub's large-file add-on
  at upload time (a P6 concern; not an owner decision yet).
